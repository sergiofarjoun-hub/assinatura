# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

Deploy-ready PWA assets (icons, web manifests, `<head>` snippet) plus the NAS shell
scripts that gave the six Hamsa Group insurance apps (Command Center, Renovações,
Claims, Sales Pipeline, Multi Cálculo, Multi Apólices) installable-PWA identity on
Android. **The project was completed on 2026-07-03** — the apps are live, served
over HTTPS by the Synology NAS `hamsa-usa` (100.94.13.31) via `tailscale serve`.
There is no application source code here; the apps themselves are Docker containers
on the NAS. Documentation is written in Brazilian Portuguese.

- `README.md` — asset inventory, per-app scopes, local validation steps.
- `DEPLOY.md` — the authoritative record: port map, exact commands executed on the
  NAS, container names/paths, post-deploy findings, final status.

## Layout

- `icons/hamsa-192.png`, `icons/hamsa-512.png` — the single brand icon (2026 gold
  hamsa symbol centered with ~68% safe zone on navy `#0b1424`). Opaque on purpose so
  one file serves as `any`, `maskable`, and `apple-touch-icon`. All six apps share it;
  apps are distinguished on the home screen by name only.
- `manifests/*.webmanifest` — one per app. These were the **initial plan**; in the
  real deploy, four apps already had their own `manifest.json` (only icons were
  swapped) and Renovações/Claims got a `manifest.json` generated by the `nas/`
  scripts. Manifests use **relative paths** (`start_url`/`scope` = `./`,
  icons `./icons/…`) so the same bundle works at any path.
- `snippets/head-snippet.html` — the block to paste into each app's `<head>`
  (manifest link, theme-color, apple-touch-icon). Also intentionally relative paths.
- `nas/` — POSIX `sh` scripts run on the NAS via `sudo sh /tmp/<script>`, in the
  order: `update-icons.sh` (Fase A) → `fase-b-crm.sh` (Fase B1) → `inspect-b2.sh`
  (read-only recon) → `fase-b2-renovacoes-claims.sh` (Fase B2).
- `preview/index.html` — local page showing the six icons side by side.
- Root `*.png`/`*.jpg` — source brand artwork (2026 identity); `hamsa_simbolo_2026.png`
  is the origin of the icons.

## Local validation

No build, lint, or test tooling. To validate manifests/icons locally (localhost is
a secure context, so no HTTPS needed):

```bash
# from the repo ROOT (so /icons and /manifests resolve)
python3 -m http.server 8080
```

Then in desktop Chrome: open `http://localhost:8080/preview/`, check
DevTools → Application → Manifest, and run Lighthouse → PWA for installability.

To regenerate icon sizes from new artwork (macOS):

```bash
sips -z 192 192 source.png --out icons/name-192.png
sips -z 512 512 source.png --out icons/name-512.png
```

## Conventions for NAS scripts (the "Hamsa protocol")

Anything that touches the NAS follows these rules — keep them if writing new scripts:

- `set -e`: **one failure → stop.** Never iterate/debug live on the NAS.
- Every modified file gets a timestamped backup next to it
  (`<file>.bak.$(date +%Y%m%d_%H%M%S)`) before being touched.
- Validate before restart: check Python syntax (and PNG signatures / minimum file
  sizes for downloads) before restarting or rebuilding any container; restore the
  backup on failure.
- Scripts download icons from this repo pinned to an **immutable commit hash**
  (`raw.githubusercontent.com/sergiofarjoun-hub/assinatura/<sha>/icons/...`),
  never from a branch.
- Scripts are POSIX `sh` (Synology), copied to `/tmp` on the NAS and run with `sudo`.
- The Tailscale CLI on Synology is not on PATH: use
  `/var/packages/Tailscale/target/bin/tailscale`, always with `sudo`.
  `serve --bg` config persists across reboots.

## Architecture decisions worth knowing

- **One HTTPS port per app** (443, 8443, 10000–10003 → each app's internal port):
  each port is its own origin, so each app is an independent PWA served at `/`,
  with no subpath asset breakage. The chosen HTTPS ports deliberately differ from
  the apps' HTTP ports so existing `http://100.94.13.31:PORT` shortcuts keep working.
  Full port map and final URLs are in `DEPLOY.md`.
- **No service worker needed**: since Chrome 108, manifest + HTTPS suffice for
  ⋮ → "Install app" (the automatic banner may not appear — install via the menu).
- **Android limitation (discovered post-deploy)**: Android ignores the port when
  associating pages with installed apps, so the six same-hostname PWAs count as one
  site — only **one** can be installed at a time on Android (desktop installs all
  six fine). Final arrangement, per Sergio's decision: only the **Command Center**
  is installed and acts as a hub whose sidebar opens the other five full-screen.
  True per-app Android icons would require migrating from ports to path scopes
  (`/renovacoes/` etc.) in all six custom servers — evaluated and deferred.
