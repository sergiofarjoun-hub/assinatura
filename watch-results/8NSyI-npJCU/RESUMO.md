## 1. Do que o vídeo trata

Jay (RoboNuggets) apresenta o **framework ARMS** — **A**pplications, **R**outines, **M**emory, **S**kills — como a forma de organizar um "sistema operacional agêntico" em volta do Claude Code, e usa o painel **RUBRIC** (produto dele) como vitrine. A tese central: o painel bonito vale 20–30% da coisa; **70% do valor está embaixo, na organização do contexto e do workspace** para que o agente trabalhe a favor de você. Ele ensina de baixo para cima (Skills → Memory → Routines → Apps), com **três níveis de maturidade por camada**, e mostra prompts prontos para o Claude Code fazer cada passo. O vídeo é também um funil para a comunidade Skool dele e para o guia PDF "Set up your Agentic OS".

### 3.7 Prompts completos mostrados em slide (transcritos dos frames)

**[8:40] SKILLS · LEVEL 2 — "Turn thick skills into a skill tree"** *(One giant SKILL.md is doing all the work. This splits it into a short router plus its own file set, so the agent reads only what the task needs.)*
```
Look through my skills folder (.claude/skills/) and find my "thick" skills – any skill where one SKILL.md file is doing all the work (roughly 150+ lines, or several different jobs mixed into one file).

Before restructuring anything, ask me these in one batch:
1. Which skills do I actually use most weeks?
2. Are any skills off-limits and not to be touched?
3. How aggressive should the split be: light cleanup, or a full file tree per skill?

Then restructure each thick skill into a skill tree:
- SKILL.md becomes a short router: what the skill is, when it triggers, and a table pointing to the right file for each job
- Each distinct job, reference list, or template moves into its own clearly named file inside the skill folder (references/, templates/, or plain .md files)
- The router tells the agent to read ONLY the file that matches the task, never everything at once

Rules:
- Do not change what any skill does, only how it is organized
- Keep every trigger and every rule. Nothing gets dropped
- A good split makes SKILL.md shorter, not longer
- Show me the before and after line counts for each skill

List the thick skills you found and your proposed split for each. Wait for my go before touching files.
```

**[10:00] SKILLS · LEVEL 3 — "Run skills from your OS with claude -p"** *(Headless mode means Claude runs a prompt without a chat window. This wires your favorite skills to buttons inside your own dashboard or software.)*
```
I want to run my Claude Code skills from buttons in my own software, without opening a chat window. This works through headless mode: the command claude -p "prompt" runs one prompt and exits.

Before you build anything, ask me these in one batch:
1. Which app should hold the buttons: my dashboard HTML, a local web app, or something else?
2. Which 3-5 skills do I run often enough to deserve a button?
3. Should each button offer options (model, effort level, an extra input field), or fire with defaults?

Then build it:
- Add one button per skill to my app. Each button runs the matching skill headlessly, for example:
  claude -p "/clean-up" --model claude-sonnet-5
- Buttons that need options get a small picker (model, effort) that feeds into the command
- Show run status next to each button (running, done, failed) and where the output landed
- If my app is plain HTML with no server, add the smallest possible local helper: one endpoint that shells out to claude -p, and wire the buttons to it
```
